# OSS Review Toolkit POC
This repository contains some scripts and configuration files that allow running ORT in
containers using a `compose` setup.

## Setting up
In order for the scripts to function we need to do the following:
1. Copy the `.env.example` file to `.env`:
```shell
cp .env.example .env
```
2. Modify the `PROJECT_DIR` variable in the `.env` file to reflect the path of the project
that we would like to process.
3. Copy the `.netrc.example` file to `.netrc`
```shell
cp .netrc.example .netrc
```
4. Generate a PAT on GitHub with basic `contents:read` permission.
5. Modify `.netrc` to contain your GitHub username instead of `[USERNAME]` and the PAT instead
of `[PERSONAL_ACCESS_TOKEN]`.

## Usage
The scripts need to run in a certain order.

### Analyze
We always start with an analysis:
```shell
./analyze.sh
```
This will create a new directory inside the project directory and places a file there that contains
the results of the analysis.
If we would like to look at the results of the analysis we can now run:
```shell
./report-analysis.sh
```
The report can be found in `[PROJECT_DIR]/ort/reporter/analysis`.

### Scan
The next step is scanning, we start a scan using the script:
```shell
./scan.sh
```
This will create a new directory inside the project directory and places a file there that contains
the results of the scan.
If we would like to look at the results we can generate a report using the script:
```shell
./report-scan.sh
```
The report can be found in `[PROJECT_DIR]/ort/reporter/scan`.

### Advise
At the same time we can now run the advisor to check for security vulnerabilities:
```shell
./advise.sh
```
It is not currently possible to get a separate report for the advisor results.

### Evaluate
We can now start the evaluator to run the results against the policies:
```shell
./evaluate.sh
```
This will create a new directory inside the project directory and places a file there that contains
the results of the evaluation.

### Report
On their own the files generated by the previous scripts aren't extremely useful. However, we can
use them to generate reports in the form of a small web app:
```shell
./report.sh
```
This will create a new directory inside the project directory and places a html file there that
contains everything needed to look at the report in a browser. It will also create two other files,
the SBOM in both CycloneDX and SPDX format.

## Caveats
ORT really needs some kind of storage to build up a database of its findings. So the first run will
be particularly slow. Subsequent runs will be much faster as it doesn't include cloning the git
repositories/downloading the source of all the dependencies and scanning all of that. In order to
facilitate that need for storage this project currently uses a Postgresql database.

*Be sure to pay attention not to delete the database volume if you wish to run it more than once!*
